# Cockpit v0.3.0 — Developer Preview

Status: release candidate, not yet published. The package version is `0.3.0`;
no v0.3.0 tag or GitHub Release has been created by this work.

This preview unifies Agent routing, fixes Codex snapshot reads during normal
database activity, and removes unused implementation paths. It remains a local,
read-only dashboard for one trusted operator. Hermes and Codex are the supported
Agents; Claude Code and Pi are not included. The intended GitHub release status
is **Pre-release**.

## Changes since v0.2.0

- Hermes-only, Codex-only, and dual-panel setups now use one Agent-scoped
  route and API structure. Hermes no longer needs a Codex configuration to
  use these routes.
- The root entry selects the remembered configured Agent or the configured
  default. Missing or invalid configuration displays actionable guidance
  without reading an Agent source or exposing configuration values.
- Removed the old unscoped pages and APIs, legacy configuration mode,
  conversation token codec, and client fallback branches.
- Codex SQLite snapshots accept normal commits and checkpoints by other
  connections. Removed source-file hash and metadata equality requirements
  that rejected consistent completed backups. Read-only connections, path
  authorization, resource limits, owned-copy validation, cleanup, and JSONL
  stable-copy checks remain in place.
- Removed executable identity and start-token fields that were recorded but
  never used in process decisions. PID and process-group checks, timeout
  handling, and conservative temporary-directory cleanup remain in place.

## Breaking changes

Old unscoped URLs return 404, with no compatibility redirects. Start at `/`
or use `/agents/<panelId>`; data APIs are under `/api/agents/<panelId>`.
An unconfigured installation displays setup guidance instead of activating
the former implicit Hermes mode. Configure sources using the
[README setup options](../../README.md#choose-your-local-sources).

Temporary directories containing the old process-record fields are preserved
by the strict record validator. There is no compatibility migration.

## Install this preview

Requirements: Node.js 24 or newer and pnpm 10.28.1. The Hermes preset targets
Hermes Agent v0.21.2 (`v2026.9.11`). Codex inspection requires macOS or Linux
and a trusted Codex CLI **exactly `0.145.0`** on the startup `PATH`.

After the `v0.3.0` tag is published, install from a clean checkout:

```bash
git clone --branch v0.3.0 --single-branch https://github.com/swen-chan/cockpit.git
cd cockpit
pnpm install --frozen-lockfile
```

Create an ignored `.env.local` using the
[README setup options](../../README.md#choose-your-local-sources), then run:

```bash
pnpm build
pnpm start
```

Open <http://127.0.0.1:3000>. Bypass proxies for `localhost`, `127.0.0.1`, and
`::1`. Keep real configuration and source data outside Git. No data import or
migration of original Agent files is performed. Update old bookmarks to the
scoped URLs described above.

## Validation

- After the version was set to `0.3.0`, the local operator reran the complete
  `pnpm verify`: formatting, types, ESLint, all 641 tests in 63 files, and the
  Webpack production build passed.
- The local operator reran all 37 Chromium browser tests on the combined
  candidate. All six synthetic scenarios passed: Hermes-only, Codex-only,
  dual-ready, Codex unavailable, unconfigured, and invalid configuration.
- Four real SQLite concurrency regressions failed with `source_busy` before
  the snapshot fix and passed afterward. Process-record cleanup passed 111
  focused lifecycle tests; four tests only checking removed field formats
  were deleted.
- Bounded reads through the candidate's production adapters passed for the
  operator's configured Hermes and Codex sources: list and selected detail,
  Codex Process, System, and configured Hermes Files and Jobs. Codex CLI was
  exactly `0.145.0`; optional Codex Files remained unconfigured. This was an
  adapter check without a listening server, not real-source browser acceptance
  or evidence of compatibility with every installation.
- The operator subsequently started this candidate with the existing local
  configuration and confirmed that the real-source UI opened and the pages
  tried were usable. This is a reported manual smoke check, not a claim that
  every checklist item or installation was individually verified.

## Known limits

- Loopback only, single user, without elevated privileges. LAN exposure,
  tunnels, port forwards, reverse proxies, cloud hosting, and multi-user access
  are unsupported.
- No automatic source discovery, import wizard, Agent execution, task resume,
  source editing, or job control. Each panel exposes only its supported views.
- Codex support remains limited to the pinned CLI and supported local storage
  layouts. Process is a filtered activity view, and paginated task details do
  not follow inherited history. Codex Files requires its own approved workspace.
- Codex rollouts over 32 MiB fail explicitly. Existing list, message, preview,
  response, and execution limits remain in place. Sources can still be busy;
  automatic retries are not included.
- Synthetic tests and limited local acceptance do not establish compatibility
  with every installation. Dates use `Asia/Shanghai`.

Read the [security policy](../../SECURITY.md) for snapshot handling and the
narrow SQLite coordination exception. Personal installation upgrades remain
separate from publishing this release. Existing tags and release notes are
not rewritten.
