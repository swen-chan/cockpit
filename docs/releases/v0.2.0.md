# Cockpit v0.2.0 — Developer Preview

This preview adds Codex inspection alongside Hermes Agent. It is a local,
read-only dashboard for one trusted operator, not a hosted service or a stable
production release. GitHub marks this release as a **Pre-release**.

## Changes since v0.1.0

- Separate Hermes and Codex panels, an explicit Agent switcher, and remembered
  last-used selection without a mandatory startup picker.
- Codex Tasks with project labels, bounded message history, and folded,
  filtered Process activity. Legacy and paginated task storage are supported
  within the documented format and size limits.
- Codex Overview and current guidance inspection; optional Files access only
  inside an explicitly approved workspace. Codex does not expose a Jobs view.
- A built-in Hermes source preset, updated setup instructions, and shared
  agent-neutral branding with separate support labels.
- Repository formatting and pre-commit checks, plus CI for types, lint, tests,
  builds, browser flows, and CodeQL security analysis.

## Install this preview

Requirements: Node.js 24 or newer and pnpm 10.28.1. Codex inspection additionally
requires macOS or Linux and a trusted Codex CLI **exactly `0.145.0`** on the
startup `PATH`. The Hermes preset targets v0.21.2 (`v2026.9.11`).

```bash
git clone --branch v0.2.0 --single-branch https://github.com/swen-chan/cockpit.git
cd cockpit
pnpm install --frozen-lockfile
```

Create an ignored `.env.local` using the
[README setup options](https://github.com/swen-chan/cockpit/blob/v0.2.0/README.md#choose-your-local-sources),
then run:

```bash
pnpm build
pnpm start
```

Open <http://127.0.0.1:3000>. Bypass proxies for `localhost`, `127.0.0.1`, and
`::1`. Do not expose this server through a LAN binding, tunnel, port forward,
or reverse proxy.

Existing Hermes setup variables remain supported. Adding Codex is optional;
no database conversion, data import, or migration of original agent files is
required. Keep private configuration and source data outside Git. Use a clean
checkout for this version rather than overwriting local work.

## Known limits

- No import wizard, automatic source discovery, cloud hosting, authentication,
  multi-user access, or universal agent compatibility.
- Codex support is limited to the pinned CLI and supported local storage
  layout. Process is a filtered activity view, not an unrestricted raw log.
- Paginated details show local recorded history only; inherited history is
  not followed. A task's project label does not grant workspace file access.
- Codex rollout files over 32 MiB fail explicitly. Other list, message, preview,
  and response limits remain in place.
- Active sources can be temporarily busy. Manual retry may be necessary;
  automatic retry is not included in this release.
- Automated tests use synthetic data. Limited real-source acceptance does not
  establish compatibility with every installation. Dates use `Asia/Shanghai`.

Read the [security policy](https://github.com/swen-chan/cockpit/blob/v0.2.0/SECURITY.md)
for read-only snapshot handling and the narrow SQLite coordination exception.
This release does not relax those boundaries or alter the existing `v0.1.0`
tag and release.
