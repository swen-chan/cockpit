# Cockpit v0.4.0 — Developer Preview

This version is a GitHub **Pre-release**.

This preview adds Claude Code to Cockpit's local, read-only dashboard. Find a
saved conversation, inspect its recorded operations, open a referenced project
file, and return to the original message. Conversations remain the default
entry; Overview, System, and Files share the selected project.

## Changes since v0.3.0

- **Claude Conversations:** readable titles, loaded-session search, pagination,
  saved messages, compaction summaries, and folded operations attached to their
  original messages. Supported operations expose bounded descriptions, selected
  check commands, sanitized result excerpts, and approved file references.
- **Claude Overview:** direct links to recent conversations, current System
  source counts, workspace access, and separate unavailable-source states.
- **Claude System:** current project and optional user instructions, explicitly
  configured memory, Skills, and custom Subagent definitions, with grouped
  search and inert document previews.
- **Claude Files:** bounded previews inside the approved project workspace,
  with a return link that restores the originating conversation position.
- **Project scope:** explicitly configure projects once and switch between them
  across all four pages. Changing project clears the previous detail selection;
  saved-session selectors and pagination tokens cannot be replayed across projects.
- **Privacy fix:** redact credential assignments with quoted JSON keys, including
  escaped quotes in their values.
- **Test dependency security:** update jsdom's transitive Undici dependency from
  8.10.0 to the compatible [8.10.2 security patch](https://github.com/nodejs/undici/releases/tag/v8.10.2).
- **Browser verification:** use the production build consistently, with separate
  scenario results and retained failure traces.

Hermes and Codex retain their existing views. Claude has no Jobs surface.

## Configure Claude Code

Requirements remain Node.js 24 or newer and pnpm 10.28.1. Claude inspection uses
pinned Claude Agent SDK **0.3.283** for saved-session reading. It does not execute
Claude and requires no Claude account or API key.

In the ignored `.env.local`, supply a saved-session directory and approved
workspace for each project:

```dotenv
COCKPIT_CLAUDE_PROJECTS='[{"id":"website","name":"Website","sessionRoot":"/absolute/path/to/claude/project-sessions","workspaceRoot":"/absolute/path/to/website","memoryRoot":"/absolute/path/to/claude/project-memory"}]'
# Optional shared user instructions, rules, skills, and subagent definitions:
COCKPIT_CLAUDE_USER_ROOT=/absolute/path/to/claude-user-directory
```

The memory and shared user roots are optional. Choose the directory containing
one project's saved UUID-named session files, not the parent containing every
project. Roots are never inferred from a saved conversation or supplied by the
browser. See the [Claude reader notes](../claude-readonly-preview.md) for exact
source coverage and limits.

The unpublished candidate's former `COCKPIT_CLAUDE_SESSION_ROOT` setting is
removed; replace it with the project configuration above. Existing v0.3.0
Hermes/Codex configurations do not require this new setting.

After the tag is published:

```bash
git clone --branch v0.4.0 --single-branch https://github.com/swen-chan/cockpit.git
cd cockpit
pnpm install --frozen-lockfile
# Create .env.local with your approved source paths before building.
pnpm build
pnpm start
```

Open <http://127.0.0.1:3000>. Bypass proxies for `localhost`, `127.0.0.1`, and
`::1`. Original Agent sources stay read-only; Cockpit does not import or migrate them.

## Validation and preview feedback

- After setting the version to `0.4.0`, the candidate passed `pnpm verify`:
  formatting, types, lint, 742 tests in 70 files, and the production build.
- The maintainer opened the local candidate and accepted the UI with clean
  fictional projects. This is a manual UI smoke check, not real Claude storage
  acceptance.
- The maintainer ran `pnpm test:browser` against the production build: all
  49 Chromium tests passed across ten synthetic scenarios, including four-page
  Claude project switching and the operation/file/session round trip. Each
  scenario recorded a passed result with no failed tests.
- The maintainer does not use Claude Code. Real-installation validation is
  intentionally being collected through early-user feedback during this preview.
  This does not establish compatibility with every Claude Code version or layout.

For a mismatch, use [GitHub Issues](https://github.com/swen-chan/cockpit/issues)
and include the Cockpit/Claude versions, operating system, affected page,
reproduction steps, and expected versus observed behavior. Use sanitized examples;
keep raw sessions, credentials, private paths, and configuration out of reports.
Use private vulnerability reporting for security issues.

## Known limits

- Loopback only, one trusted local operator, without elevated privileges. No
  cloud, remote, or multi-user mode; no source editing or Agent execution.
- Session reading covers immediate saved files in explicitly configured project
  directories. No automatic discovery, nested subagent transcripts, worktree
  aggregation, Hooks/MCP dashboard, cost totals, or live execution status.
- System shows currently discovered files, not the effective configuration of a
  historical session. Skills/Subagents are definitions, not execution evidence.
- Session/file return links expire when Cockpit restarts; reopen the conversation
  from its list. They are not permanent bookmarks or share links.
- File previews show current content. Recorded check output is historical
  evidence and does not independently prove that a task succeeded.
- Existing bounded-read and privacy policies remain in force. Unsupported or
  unsafe details are omitted, and partial readings are labeled.

See [SECURITY.md](../../SECURITY.md) for the local trust model and source boundaries.
